# ADR-0006: Agent enrollment, computer identity and policy distribution (Phase 3)

- Status: Accepted (2026-09-26). Implements ADR-0003 items 2–3.

## Decisions

1. **Installation.** An administrator runs `OfficeSecurity.Agent.exe install --server … --pairing-code …
   --enrollment-code …` once per computer, as a local administrator. The installer:
   - verifies the server with the pairing code
   - copies the program to `C:\Program Files\OfficeSecurity\Agent`
   - writes its configuration to `C:\ProgramData\OfficeSecurity\Agent`, which is ACL-restricted to SYSTEM and
     Administrators
   - registers the **OfficeSecurityAgent** Windows Service with these settings:

   | Setting | Value |
   |---|---|
   | Start type | Automatic |
   | Account | LocalSystem |
   | Recovery | Restart after 5 s, 5 s and 30 s |
   | Service permissions | Only SYSTEM and Administrators may stop, reconfigure or delete it |

2. **Computer key.** The service creates an ECDSA P-256 **machine key that cannot be exported**:
   - in the TPM when one is usable (Microsoft Platform Crypto Provider)
   - otherwise in the Microsoft Software Key Storage Provider

   Only a certificate request (public key) leaves the computer.

3. **Enrollment codes** are single-use and valid for 24 hours; only their hash is stored. A registered computer
   stays **Waiting for approval** until an administrator approves it in the dashboard. Only then does the server
   issue a client certificate (CN = computer id, valid 2 years, client-authentication only) from its private CA.
   Until approval the agent polls with a random poll token.

4. **Mutual TLS.** Every call from an approved agent authenticates with that certificate. The server accepts it
   only if all of these hold:
   - it chains to the server's own CA
   - it is valid
   - its SHA-256 thumbprint belongs to a computer that is currently *approved*

   Removing a computer from management takes effect on its next request.

5. **Policies.** Administrators edit named policies; one is the default.
   - Each computer's *effective* policy is its assigned policy (or the default), signed with the separate policy
     key.
   - Its version is a per-computer counter. The counter increases whenever the assigned policy changes or the
     policy content changes, so agents always see a strictly higher version.
   - The agent verifies each policy before use: signature with the pinned key, this computer's id, and a newer
     version. It then applies the policy and caches the signed copy.
   - At start-up the cache is verified again. A modified cache is rejected, deleted and reported as a
     `PolicyTamperAttempt` event.

6. **Offline operation.** When the server is unreachable, the agent:
   - keeps enforcing the last valid policy
   - queues events in a local SQLite file (up to 100,000 unsent events; the oldest are discarded beyond that)
   - retries with back-off (15 s up to 5 min)

   Uploads are idempotent: each event carries an id generated by the agent.

7. **Inventory.** Hardware and Windows details (WMI and registry) are sent every 15 minutes. Removable storage,
   phone/camera (WPD), optical and Bluetooth devices are checked every 15 seconds. Connections and
   disconnections are logged as `DeviceConnected` / `DeviceDisconnected` events; this is the USB connection log.

8. **Staff sign-in restricted to computers.**
   - The staff application asks the local agent, over a named pipe, for a one-time **computer ticket** (valid
     2 minutes). The agent obtains it from the server over mutual TLS.
   - Staff who are assigned to computers can sign in only with a ticket from one of those computers. Staff
     without assignments are unrestricted.
   - The pipe:
     - denies network access
     - offers only "status" and "login ticket"
     - rate-limits tickets
   - Before trusting a pipe, the staff application verifies (Windows API `GetNamedPipeServerProcessId`) that the
     serving process is the installed agent program in Program Files. This defeats a fake "agent" started by a
     user.

9. **Uninstall** requires a local administrator. It stops and deletes the service, and deletes the machine key
   and agent data.
   - *Limitation:* a server-issued uninstall authorization code is planned for Phase 7.
   - *Limitation:* a local administrator can always remove the agent (plan §14).
